# AI-Powered Personalized Learning Path Recommender

Tell it what you want to be able to do. It gives you an ordered, milestone-grouped
course roadmap for AI/ML engineering — and for every single course, it can tell you
exactly which prerequisite edge put it there.

> *"Your goal Retrieval-Augmented Generation requires Vector Databases, which requires
> Embeddings, which requires Transformer Architecture — and you do not have Embeddings
> yet. This course teaches it. It is placed here because PyTorch comes from Deep Learning
> from the Foundations earlier in your path. Finishing it unblocks 2 later courses."*

That sentence is not generated by a language model. It is read off a graph.

## The idea: a learning path is a prerequisite graph problem

Most "AI learning path" tools ask a language model to write the curriculum. That
produces plausible-looking lists with three specific failure modes:

| LLM-generated paths | This system |
|---|---|
| Order is a stylistic choice. Nothing stops it putting Transformers before Backpropagation. | Order is a **topological sort**. A course *cannot* appear before the courses teaching its prerequisites — that is a structural guarantee, not a tendency. |
| "Why this course?" gets answered after the fact, by asking the model to justify its own output. It will always produce a confident answer, including for a mistake. | "Why this course?" is a **graph traversal**: the actual chain of `requires` edges from the missing skill up to your goal. If no such chain exists, the course is not in your path. |
| Telling it "I already know pandas" means re-prompting and hoping. | Knowing a skill removes a **node** from the gap set. Everything that existed only to reach it disappears, deterministically, in one recomputation. |
| Same prompt, different day, different path. | Same profile always produces the same path. Ties are broken by a documented rule, never arbitrarily. |

### The pipeline

```
free-text goal ──[LLM, with keyword fallback]──▶ target skill ids
                                                      │
        learner profile (known skills) ───────────────┤
                                                      ▼
                          transitive prerequisite closure  (graph traversal)
                                     minus possessed skills
                                                      ▼
                                        GAP: the skills you still need
                                                      ▼
                        topological sort  (Kahn, deterministic tie-break)
                                                      ▼
                     greedy set-cover course selection  (tag overlap + heuristics)
                                                      ▼
                        grouping into 3-5 named milestone phases
                                                      ▼
                    explanations read directly off the prerequisite edges
```

### It will not guess

Ask for something the graph does not cover and it says so, instead of quietly
planning something else:

```
"I want to be a web developer"      -> out of domain, nothing close in the graph
"I want to work with models"        -> asks: Model Deployment? RNNs? RLHF? LLM Fundamentals?
"asdkjh qwerty zzz"                 -> out of domain (and so does an empty goal)
```

Reinforcement learning used to be the standing example here: the graph had no RL node, so
the parser declined rather than mapping RL onto RLHF, which is an LLM fine-tuning technique
and not RL. The vocabulary gap log recorded the miss, the branch was added, and the goal now
lands in it — `"I want to do reinforcement learning"` on Reinforcement Learning Fundamentals,
and even `"I want to do reinforcment lerning"` on the RL branch through the typo. Neither
resolves to RLHF, which the suite asserts. That is the loop this design is meant to have:
refuse, record, then fix the content.

Goal parsing runs four scored layers - curated phrases, 803 curated aliases
(LangChain, Pinecone, vLLM, Kubernetes, XGBoost...), fuzzy matching for typos,
and TF-IDF cosine for paraphrase like "make computers understand pictures".
Above a confidence threshold it plans; below it, it hands back ranked candidates
and asks. Whatever it could not map at all is recorded in a vocabulary gap log
(`GET /api/vocab-gaps`) - the terms learners actually used that the graph has
never heard of, which is the content backlog written by use rather than guesswork.

The language model touches **step 1 only** — turning your sentence into skill ids from
a fixed vocabulary — plus an optional cosmetic rewrite of an explanation the graph has
already produced. It never chooses courses, never orders them, and never decides why
something is necessary.

## Ollama is optional

The app calls a local [Ollama](https://ollama.com) instance (`llama3.2:3b`) for exactly
two things:

1. **Goal → target skills.** Fallback: `keyword_match_targets()`, a deterministic phrase
   matcher over the same skill vocabulary.
2. **Prettifying an explanation.** Fallback: the graph-derived sentences themselves.

(Chat is a third, convenience use — and it also computes a correct deterministic answer
first, then merely asks the model to rephrase it.)

Every call goes through one wrapper with a hard **20-second timeout** that returns `None`
on any failure at all — connection refused, timeout, bad JSON, HTTP error, unpulled model.
**Kill Ollama entirely and every feature still works.** The paths, the ordering, the
explanations and the replanning are bit-for-bit identical; only the phrasing changes.

The server says which mode it is in at startup:

```
  OLLAMA: NOT REACHABLE (ConnectionError: ...)
  -> DETERMINISTIC MODE: goals parsed by keyword matching, explanations
     read straight off the graph. Nothing is missing except nicer
     phrasing - this is a fully supported way to run the app.
```

To enable it: `ollama pull llama3.2:3b` and make sure `ollama serve` is running. Use a
different model with `OLLAMA_MODEL=<name>` (the banner lists what you have pulled).
Note that a **cold model load can exceed the 20s cap**, so the very first request after
starting Ollama may fall back — the second will not.

## What else the graph can tell you

Because the curriculum is a graph rather than a list, the app can answer questions a
ranked list cannot:

| Feature | Question it answers |
|---|---|
| **Skip risk** | *"What breaks if I skip this?"* Walks forward from what a course teaches to the skills that would go unlearned and the later courses stranded, and says whether your goal is among the casualties. |
| **Leverage** | *"Which course is worth the most?"* Ranks courses by how much of the rest of the plan they unblock. A dull foundations course can unblock 19 others. |
| **Slot windows** | *"Why is this at step 11 and not step 3?"* The earliest and latest slot each course could occupy in any valid order, and its slack. |
| **Critical path** | *"What actually determines how long this takes?"* The zero-slack chain, measured in hours (CPM). 16 of 20 courses and 339h are forced sequence; the rest could move. |
| **Readiness** | *"Am I ready for this course?"* For any course in the catalogue, in your plan or not: how many skills away you are and what preparation closes the gap. |
| **Alternative routes** | Five selection strategies - balanced, shortest, free-first, project-led, thorough - over the same required skills. Switch with one click; the graph guarantees all of them are valid. |
| **Goal comparison** | *"What would a second goal cost me?"* RAG and fine-tuning share 76% of their courses, so adding the second costs 1 course and 14h rather than 369h. |
| **Time budget** | *"I have 5 hours a week for 12 weeks - how far do I get?"* Names the milestone that slips past the deadline. |
| **Your own pace** | Log what a course actually took and every later forecast uses your ratio instead of the catalogue's estimate. |
| **Refreshers** | Spaced review timed by graph position: a skill resurfaces only when a course that directly requires it is coming up. |
| **History import** | Paste your completed courses; they run through the same resolver, and what it cannot match is reported rather than credited. |
| **Graph health** | The maintainer's view: 27 of 134 skills are taught by exactly one course, which is exactly where the curriculum is fragile. |

Graded self-assessment runs underneath several of these: *heard of / can use / can teach*,
where only "can use" and above counts as known, and "heard of" earns a shorter refresher
course rather than the full one.

## Architecture

```
main.py         FastAPI: HTTP, learner state, Ollama calls + fallbacks
  │
  ├── engine.py       the whole recommender, pure Python, no model in the loop
  │     ├── load_graph()      DAG validation, fails loudly on a cycle
  │     ├── gap_analysis()    transitive closure minus possessed skills
  │     ├── topo_order()      Kahn with a stable tie-break
  │     ├── select_courses()  greedy set cover + heuristic scoring
  │     ├── build_path()      milestones + card-to-card prerequisite links
  │     ├── explain()         structured trace from prerequisite edges
  │     └── replan()          remaining path + progress from current state
  │
  ├── data/skills.json    134 skills, 208 prerequisite edges, max depth 20
  ├── data/courses.json   239 courses, 2.1 per skill, real competition
  ├── learners.json       the only persistence (created on first intake)
  └── static/index.html   the entire frontend, one file, CDN React + Tailwind
```

### Data

`data/skills.json` is a DAG of 134 AI/ML engineering skills in eight categories -
Foundations, Data & Statistics, Core Machine Learning, Deep Learning, Reinforcement
Learning, LLM Systems, Production & MLOps, and AI Safety & Governance. The spine runs
`python → numpy → pandas → data-viz → statistics → sklearn-basics → supervised-learning
→ model-evaluation → feature-engineering → deep-learning-fundamentals → pytorch → cnns
→ transformers → embeddings → vector-databases → rag → llm-finetuning`, with branches
for SQL and data engineering, classical ML (linear models, trees, SVMs, interpretability,
calibration), deep learning (detection, segmentation, autoencoders, GANs, diffusion, GNNs,
speech, multimodal), a full reinforcement-learning branch from MDPs through actor-critic,
LLM systems (structured outputs, reranking, agent memory, injection defence, inference
optimisation), MLOps (Kubernetes, IaC, feature stores, progressive delivery) and AI safety
(fairness, robustness, privacy-preserving ML, governance).

RLHF now requires policy gradients, which is what a reinforcement-learning branch should
imply - before it existed, "I want to do reinforcement learning" was a documented gap the
parser refused to answer.

`data/courses.json` has 239 courses from 23 realistic providers (Coursera, Udemy,
fast.ai, DeepLearning.AI, Hugging Face, Kaggle Learn, MIT OCW and others), 34 of them
free. Each declares what it **teaches**, what it **requires**, its level, hours and tags.
At 2.1 courses per skill most skills have competing options, so selection is a real
decision rather than a lookup - and the 27 that do not are reported by
`GET /api/graph/health` as the fragile ones.

Both files are validated at load: unknown ids, duplicate ids, cycles, a course requiring
a skill it teaches, or a skill no course teaches all raise `GraphError` and stop the app.

## What the three test personas produce

`python scripts/test_personas.py` runs these headless and asserts the invariants
(no course before its prerequisites, every gap skill covered, every goal reached,
no redundant course):

| Persona | Goal | Result |
|---|---|---|
| Complete beginner | "I want to become an ML engineer" | 22 skills → **17 courses, 321h**, 4 phases |
| Python dev, no ML | "I want to build RAG chatbots" | 27 skills → **20 courses, 393h**, 4 phases |
| Knows scikit-learn | "I want to fine-tune LLMs" | 16 skills → **12 courses, 231h**, 3 phases |

The third persona's path is short precisely because knowing scikit-learn credits
everything below it in the graph — Python, calculus, linear algebra, probability,
statistics, pandas — without them being listed.

There are six suites in total:

```bash
python scripts/test_personas.py        # three personas, path invariants
python scripts/test_goal_parsing.py    # the resolver, including refusing to guess
python scripts/test_analytics.py       # skip risk, leverage, slack, routes, comparison
python scripts/test_learner_model.py   # self-assessment, pace, budgets, refreshers, import
python scripts/test_api.py             # every core endpoint end to end
python scripts/test_features_api.py    # the analytics and learner-modelling endpoints
python scripts/benchmark.py            # performance budget for a growing graph
```

The benchmark exists because the graph is meant to keep growing. Every request recomputes
its path from scratch - there is no cache to invalidate - so the budget is what keeps that
honest. On the current 134-skill, 239-course graph a path builds in **0.3 ms**, a full
replan in **0.4 ms**, all five alternative routes in **1.8 ms** and goal parsing in
**4 ms**.

Run it once with Ollama up and once with it killed; the only difference in the output is
the `source` fields flipping between `ollama` and the deterministic fallbacks.

## Using it

1. Type a goal, pick a level, tick the skills you already have (or load a demo persona).
2. Read the roadmap. Hover a card to see which courses feed it and which it unblocks, and
   use the phase pills to narrow the timeline to one milestone at a time.
3. Hit **Why this?** on anything that looks surprising — the prerequisite chain is right
   there.
4. Hit **Mark complete** and watch the plan shrink.
5. Use **Feedback → Already know this** to skip material; everything that only existed to
   reach that skill vanishes from the path.
6. Click any skill chip to open that node of the graph — its prerequisites, what it
   unlocks, which courses teach it and where you stand on it. Every skill in the inspector
   is clickable, so you can walk the graph in any direction. The rail also has a
   browse-everything view and a short "how this plan is built" panel.
7. Changing your goal keeps your progress by default: completed courses and everything
   you have learned stay in your profile, and the new gap is computed from where you are.
   Unticking that box is what starts a brand new learner.
